1.全双工通信与半双工通信
1-1.全双工
（1）特点：可以双向同时传输数据，通信系统的两端都配置了发送器和接收器，无需切换所以没有因切换操作而产生的时间延迟
（2）应用场景：交互式应用，如远程监测和控制系统，电话机
1-2.半双工
（1）特点：可以双向通信，大速不能同时进行，同一时刻信息只能单向传输，发送端和接收端需要切换角色
（2）应用场景：对讲机
1-0.单工通信（补）
仅能单向传输信息 如广播

2.SPI，串行外设接口
2-1.基础认识
·一种高速、【全双工】的同步串行通信协议，主要用于控制器与一个或多个外围设备之间的短距离通信
·SPI 总线通常使用四根信号线——SCLK（串行时钟，由主机产生）、PICO/MOSI（主设备输出/从设备输入）、POCI/MISO（主设备输入/从设备输出）、CS（片选，低电平有效）

*PICO/MOSI:（Peripheral In Controller Out/Master Out Slave In）
主设备（控制器/Controller）输出、从设备（外设/Peripheral）输入的数据线。在传统的命名中叫 MOSI，由于现代技术术语去除了 Master/Slave 的称谓，现在常称为 PICO。数据从主机发往从机。

*POCI/MISO:POCI (Peripheral Out Controller In) / MISO (Master In Slave Out)。
从设备（外设）输出、主设备（控制器）输入的数据线。传统命名叫 MISO。数据从从机发往主机。

*CS:（Chip Select，片选）
也称 SS (Slave Select)。SPI 总线没有像 I2C 那样的设备地址机制，主机通过拉低某个从设备的 CS 引脚（通常低电平有效）来“选中”该设备进行通信。每个从设备通常需要一根独立的 CS 线。
片选的作用：当某个从设备的 CS 引脚为高电平时，它的 MISO 引脚会处于高阻态（高阻抗，相当于断开），不会干扰总线；只有 CS 被拉低的从设备，才会激活它的 MISO 引脚并驱动总线。这样可以避免发生电平冲突。
2-2.特点
·全双工：数据可以同时发送和接收。
·同步通信：使用共享时钟信号，确保精确的数据传输时序。
·无标准协议格式：SPI 不定义标准通信格式，允许开发者根据具体应用需求定制协议。
·无地址机制：通过片选（CS）线选择从设备，而非软件地址。
·速度高：传输速率可超过 1 Mbps，甚至达到 10 Mbps 至 100 Mbps。
*通信协议及格式：
通信双方为了实现数据交换而制定的“规则”。包含物理层（电平、引脚）和协议层（数据帧结构、起始/停止位、校验方式、时钟极性/相位等）。在 SPI 中，因为没有统一的标准协议，开发者需要自己“定义通信协议”（如：数据是高位先发还是低位先发、时钟空闲状态是高还是低等）。
2-3.优缺点
（1）优点：速度快于异步串行通信；接收硬件可以是简单的移位寄存器；支持多个从设备。
（2）缺点：需要更多信号线（四线 vs 两线）；通信协议需预先明确定义；主机必须控制所有通信，从设备不能直接相互通信；通常每个从设备需要单独的片选线，从设备数量多时布线复杂。
*异步串行通信：发送方和接收方没有共享时钟线（不需要 SCLK），而是依靠预先约定的波特率（Baud Rate）进行同步，并通过数据帧的起始位和停止位来判断一帧数据的开始和结束。典型代表是 UART。它与 SPI、I2C 这类“同步通信”相对。
*移位寄存器：一种数字电路部件。在串行通信中，发送方将并行数据放入移位寄存器，然后一位一位地移出到数据线上；接收方则将数据线上的电平一位一位地移入移位寄存器，最后转为并行数据。这是串行通信硬件（如 SPI 硬件外设）最底层的实现基础。
*定义通信协议：由于 SPI 没有严格的标准规定数据格式，开发者必须根据具体外设的数据手册（Datasheet），在代码中明确定义通信规则（例如：CPOL=0, CPHA=0，8位数据，MSB先行等），这称为定义通信协议。
*片选线：在多从机 SPI 架构中，主机通过拉低对应从机的片选线来建立通信链路，未被选中的从机其 MISO 引脚需处于高阻态，以免干扰总线。
2-4.应用典例
MCU 与 E2PROM、ADC、显示驱动器、SD 卡、液晶显示屏等外设的连接
*E2PROM：Electrically Erasable Programmable Read-Only Memory（电可擦可编程只读存储器）。
解释：一种非易失性存储器，断电后数据不丢失。常用于存储单片机的配置参数、校准数据。它常使用 I2C 接口（如 AT24C02）或 SPI 接口（如 25LC256）与主控通信。
*SD卡：Secure Digital Card（安全数字存储卡）。
解释：广泛使用的非易失性存储介质。它原生支持 SD 总线（1位/4位），但也支持 SPI 模式。在单片机开发中，为了简化硬件和软件设计，经常使用 SPI 模式来读写 SD 卡，虽然速度比原生模式慢，但占用引脚少且驱动编写简单。

3. C 板 SPI 配置过程（BMI088）

3-1. 引脚重映射
STM32F407 的 SPI1 默认引脚为 PA5(SCK)/PA6(MISO)/PA7(MOSI)，但 C 板上 PA5/PA6 被摄像头接口(DCMI)与 ADC 占用，故 SPI1 重映射为：
- SCK  = PB3
- MISO = PB4
- MOSI = PA7（未变）
其中 PB3/PB4 原为 JTAG 调试脚，因 SYS 已设为 SWD（关闭 JTAG）而释放。

3-2. 参数
- 时钟分频 /16 → 84 MHz ÷ 16 = 5.25 MHz（BMI088 手册上限 10 MHz）
- 8 位数据、MSB 先行、CPOL=Low、CPHA=1 Edge（即 SPI Mode 0，BMI088 支持）

3-3. 片选（软件 CS）
BMI088 内部含加速度计 + 陀螺仪两颗传感器，共用一套 SPI 线、各用一个 CS。不用硬件 NSS，改用普通 GPIO 手动拉低选中（需两路独立 CS，且读数据时 CS 需全程保持低电平）：
- 加速度计 CS = PA4（GPIO 输出，初始高）
- 陀螺仪   CS = PB0（GPIO 输出，初始高）
